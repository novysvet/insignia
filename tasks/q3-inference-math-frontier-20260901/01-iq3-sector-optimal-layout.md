Expected effort: 6–12 hours. CPU and mathematics only.

## Exact setting

The live GLM-5.3-Flash routed gate/up matrices are normally IQ3_XXS. One output
row has 4096 weights, hence sixteen 256-weight blocks. A block is exactly 98
bytes:

- bytes 0–1: FP16 super-scale `d`;
- bytes 2–65: 64 codebook-index bytes;
- bytes 66–97: eight little-endian 32-bit words. Each word carries four
  parity-compressed 7-bit sign groups in bits 0–27 and a 4-bit local scale in
  bits 28–31.

Thus a row is 1,568 bytes and an expert gate or up matrix is 3,211,264 bytes.
The current GPU map assigns one warp to an output row. Four eight-lane cohorts
consume four blocks per wave; each lane consumes one 32-weight subgroup. The
original AoS block stride is 98 bytes, so 32-bit loads frequently straddle
boundaries. A current byte-neutral candidate stores, per row, all 32 scale
bytes, then all 1,024 index bytes, then all 512 auxiliary bytes. It improves
some multiplicities but not all: seven-run medians in microseconds are roughly
raw/repacked R1 10.221/10.046 before the later CTA change, R2 12.082/12.791
before streaming, R4 17.067/16.102, and R8 27.717/27.536. After specialized
dispatch, repacked R1 is 8.414 and R2 is 11.081.

Assume an Ada warp has 32 lanes and global/L1 requests are serviced in 32-byte
sectors. Treat the exact cache-line aggregation rule as a parameter; solve at
least 32-byte sectors and 128-byte lines made of four sectors. A layout may
permute bytes within each row but must be reversible, have exactly 1,568 bytes,
preserve independent row access, and require at most affine address arithmetic
plus compile-time constants. No padding, duplicated metadata, or expanded
weights are allowed.

## The problem

Define the simultaneous address sets generated by one warp for every wave and
every field load. Find a layout and lane/cohort assignment minimizing a
weighted objective

`J = sectors + lambda * lines + mu * distinct_base_registers + nu * integer_ops`,

first symbolically in nonnegative parameters and then over realistic parameter
ranges. Prove one of the following:

1. the current scale/index/aux SoA is Pareto-optimal among all legal layouts;
2. a strictly dominating layout exists, with an explicit bijection and decoder;
3. no single layout dominates, and a finite partition of parameter space gives
   the optimal layouts and dispatch boundary.

The proof must include lower bounds on unavoidable sectors for the index and
auxiliary planes. Account for row starts modulo 32 and 128, all sixteen blocks,
both 2,048- and 4,096-column geometries, and the fact that eight routed experts
may occupy unrelated base addresses. Do not assume a favorable allocation
alignment unless you make it an explicit storage invariant and price it.

Then jointly optimize the lane assignment. You may change which lane handles a
subgroup or block, but reduction must still produce one output row per warp and
each weight must be decoded exactly once per token row. Prove that your mapping
is optimal or provide an approximation ratio relative to an integer-program
lower bound.

## Required deliverables

- A rigorous model, theorem, and proof or counterexample.
- A deterministic Python/C++ sector simulator that enumerates every row
  alignment and validates the claimed counts.
- An ILP/SAT/SMT formulation plus a machine-checkable certificate for small
  instances; explain how it scales to sixteen blocks.
- Pseudocode for forward and inverse repacking and the exact CUDA address
  expressions.
- An adversarial suite including worst row alignment, eight unrelated expert
  bases, and pathological lane permutations.
- A predicted A/B table for R=1,2,4,8. Label it as a prediction, not a measured
  speedup.
- A final promote/kill rule. A useful default rule is: reject any layout whose
  best provable sector reduction is below 3% or which adds more address
  instructions than sectors removed.
